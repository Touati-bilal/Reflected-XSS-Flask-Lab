/lab — Comprendre le flux de la donnee

Ce schema montre le trajet complet d'une valeur saisie par l'utilisateur jusqu'a son affichage dans le navigateur.

Flux general (requete / reponse)

User input
(ce que vous tapez)
↓
q parameter
/search?q=...
↓
Server
app.py lit request.args['q']
↓
HTML response
q insere dans le HTML
↓
Browser
affiche / execute le HTML recu

A chaque etape, la donnee reste "la meme chaine de caracteres" — c'est uniquement la maniere dont le serveur l'insere dans le HTML (etape "HTML response") qui determine si le navigateur va l'executer ou simplement l'afficher.

Attack flow (schema d'attaque simple)

Exemple : un lien contenant un payload est partage avec une victime.

Attaquant
construit /search?q=<script>...</script>
↓
Victime
clique sur le lien
↓
Navigateur de la victime
envoie GET /search?q=...
↓
Serveur vulnerable
insere q sans echapper
↓
Navigateur de la victime
execute le script injecte

Dans un vrai scenario, ce script pourrait lire des cookies, rediriger la victime, ou modifier la page (defacement) — tout cela dans le contexte du site vulnerable, avec les droits de la victime. Ici, notre labo se contente d'un alert() local pour illustrer que du code s'execute reellement.

Retournez sur /search pour tester ce flux vous-meme avec les exemples "Try it yourself".
